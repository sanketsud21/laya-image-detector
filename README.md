# Laya Image Detector (demo)

A small, educational project that classifies images as **real** or **AI-generated**, built to learn how image models work and how they plug into a decision layer like Laya's.

> **This is a demo, not a forensic tool.** Scores describe what a model learned from its training data. They are not proof that an image was or was not generated by AI. Detectors fail on new generators, compressed or edited images, and real photos that resemble generated ones. Do not use this to accuse anyone.

## What it does

1. Extracts image embeddings with a frozen CLIP encoder (`openai/clip-vit-base-patch32`).
2. Trains a logistic regression on those embeddings to separate real from AI images.
3. Evaluates honestly, including on an AI generator the model never saw during training.
4. Serves the detector through a small Gradio app.

The point is to understand each step, so the code favors clarity over performance.

## Out of scope

- Production throughput, serving, or monitoring
- Robustness to heavy recompression, screenshots, or adversarial edits
- Edited or hybrid images (inpainting, retouching)
- Provenance standards such as C2PA or SynthID
- Identifying which generator made an image

## Setup

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pytest
```

CPU is enough. A GPU just makes embedding faster.

## OpenRouter API key

For `model_connect.py`, add your key to the root `.env` file:

```dotenv
OPENROUTER_API_KEY=your_openrouter_api_key
```

Keep `.env` local; it is ignored by git.

## Data

Place images in `data/raw/`, one folder per source. The folder name is the **generator**, and `real` is reserved for real photographs:

```
data/raw/
├── real/     # real photos            -> label 0
├── sd15/     # Stable Diffusion 1.5   -> label 1
└── sdxl/     # any other generator    -> label 1
```

A good starting point is **CIFAKE** (search for "CIFAKE" on Kaggle). It contains real CIFAR-10 images and Stable Diffusion outputs in `REAL` and `FAKE` folders. Rename them to `data/raw/real/` and `data/raw/sd/`. Check the dataset's license before sharing derived data.

CIFAKE images are 32×32, which is far below real-world resolution. Treat it as a teaching dataset. Results on it will not transfer directly to photos from a phone or social media.

Keep data out of git. The `data/` folder is already gitignored.

## Running the pipeline

```bash
# M0/M2: build the manifest (path, label, generator)
python -m src.data --raw data/raw --out data/processed/manifest.csv

# M2: random-split baseline
python -m src.train

# M3: hold out one generator entirely
python -m src.train --holdout sdxl

# Demo UI (requires a trained model in models/)
python app.py
```

Each run writes metrics to `reports/metrics.json`. Embeddings are cached in `data/processed/embeddings.npz`, and the cache is invalidated automatically if the manifest or encoder changes.

## Known limitations

- The score uses a single fixed threshold pair (`low`, `high`) that was not tuned on a validation set. Treat the "uncertain" band as a placeholder.
- The CLIP processor center-crops to 224×224, which can discard generation artifacts near the edges. This is a deliberate lesson, documented in the learning log.
- Logistic regression on frozen features is a baseline. Accuracy on a held-out generator is expected to be noticeably lower than on the random split.
